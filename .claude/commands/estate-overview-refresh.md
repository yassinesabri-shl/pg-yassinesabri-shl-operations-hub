# `/estate-overview-refresh`

**This file is a contract, not an integration.** It defines the procedure, the preconditions and
the stopping condition. The code host and the pull-request mechanism are yours. The command reads
the hub trunk only. It reads no spoke, no tracker and no wiki.

**Purpose.** Keep `docs/estate/overview.md` true. The estate overview is one plain-English page on
what the estate is. `/feature` reads it before its interview, and `/decompose` reads it before its
repository map. With no overview on the trunk, this command writes one from the hub's own files.
With an overview on the trunk, it finds the source files that changed since the last commit that
changed the page. It edits the page only when a change makes the page false or incomplete.

**Who runs it.** A person types it in the hub. Run it once during the install, after every spoke
is on the list and surveyed. Run it again after a merge of `/add-repo` or `/survey-repo`, or at any
time. No CI job and no other command runs it. A merge by a person is the only acceptance.

## Inputs

| Input | Form | Where it comes from |
|---|---|---|
| `scripts/plan-overview.mjs` | Prints the trunk tip `T`, the last commit `P` that changed the overview, and each source file that changed between them | Installed with the hub |
| `docs/estate/repositories.json` | The list of spokes, by id | `/add-repo` |
| `docs/estate/surveys/<ID>.md` | One service survey for each spoke. Section 1 (Serves) and section 2 (Calls) are the sources | `/survey-repo` |
| `docs/requirements/<SLUG>/requirements.md` | The merged requirements documents | `/feature` |
| `docs/architecture/*.md`, `docs/standards/*.md` | The decision records and the standards | `/add-context` |
| `docs/estate/_TEMPLATE.overview.md` | The shape of the page | Installed with the hub |
| `scripts/check-context.mjs` | The header and parse check, run before the pull request opens | Installed with the hub |

A file whose name starts with `_TEMPLATE` is not a source. A file under
`docs/requirements/<SLUG>/runs/` is not a source.

## Preconditions

1. The working directory is the hub root, on a clean checkout of the trunk.
2. No pull request is open on branch `context/estate-overview`. If one is open, stop and name it.
3. No local branch `context/estate-overview` exists. If one exists, stop and name it. The person
   deletes it.

## What it does

1. **Check the preconditions.** Stop if one fails.
2. **Run the script.**

   ```bash
   node scripts/plan-overview.mjs
   ```

   | Exit | Output | Next |
   |---|---|---|
   | 0 | `since <P> at <T>`, `no source change` | Say "the overview is current at `<T>`" and stop. Cut no branch |
   | 1 | `at <T>`, `no overview` | Step 3 |
   | 1 | `since <P> at <T>`, then one `<status>\t<path>` line for each changed source | Step 4 |
   | 2 | `CANNOT VERIFY: <reason>` | Name the cause and stop |
   | 3 or 4 | the error | Print the error and stop |

3. **Generate.** Cut the branch from `T`. Its working tree is then the trunk at `T`.

   ```bash
   git checkout -b context/estate-overview <T>
   ```

   Read every source file in the working tree. Write the page from the template by the rules in
   "What belongs in each section". Drop the template's comment block. Ask the person one batch
   question for these values:
   - the owner role for the header,
   - "who to ask" for each spoke,
   - "who owns it" for each system outside the estate.

   Give each value as a role, never a person. A cell with no answer gets this full line:
   `UNRESOLVED — who to ask for <id>. Owner: lead architect. Resolves: the lead architect names a role.`
   Go to step 6.
4. **Refresh.** For each listed file, read its diff:

   ```bash
   git diff <P> <T> -- '<path>'
   ```

   Answer one question for each file: does the page now state something false, or lack
   something that a rule in "What belongs in each section" requires? Record the answer and the
   source line that forces it.
5. **Stop, or edit.** If every answer is "no", print each file and the reason it needs no change.
   Then stop. Cut no branch and open no pull request. Otherwise cut the branch from `T`, as step
   3 does. Edit only the lines that a "yes" answer names. Ask for an owner role only for a row
   that the edit adds.
6. **Set the header.**

   | Key | Value |
   |---|---|
   | `owner` | The current value. With no page, the role the person gave in step 3 |
   | `revision` | The run date, `YYYY-MM-DD` |
   | `origin` | `generated by /estate-overview-refresh from hub@<T>` |
   | `name`, `description`, `globs`, `alwaysApply`, `kind` | `estate-overview`, one sentence on the estate, `[]`, `false`, `estate-overview`, as the kind fixes them |

7. **Check the page.** Run the check. Fix each finding in the page and run the check again. Never
   change the check.

   ```bash
   node scripts/check-context.mjs --offline           # exit 0, or fix and run again
   ```

8. **Commit and open the pull request.**

   ```bash
   git add docs/estate/overview.md
   node scripts/harness-commit.mjs -m "docs(context): refresh estate-overview"
   # open the pull request in the hub against the trunk, its description ending with the watermark line
   ```

   The pull request carries the one page. Its description ends with the watermark, the line
   `Generated-by: SHL Agentic Harness` on its own after the normal description
   (`.claude/rules/watermark.md`). The description lists:
   - the commits `P` and `T`, or `T` alone for a new page,
   - each edit and the source line that forces it,
   - each listed file that needs no change, and the reason,
   - each word that a source uses and does not define.

## What belongs in each section

These rules decide both a new page and a refresh. Do not make an edit that no rule and no source
line supports.

| Section of the page | What goes in | Changes only when |
|---|---|---|
| 1. What the system does | One paragraph. The path of a transaction, from the calls between spokes in survey section 2: the rows whose Provider is a repository id | A spoke joins or leaves, or a call between spokes is added or removed |
| 2. The parts | One row for each id in `repositories.json`, and no other row. "What it is for" comes from survey section 1 (Serves), in the business's words. The registry `purpose` orients the session and is never the text | An id joins or leaves, or the meaning of survey section 1 changes. A change to the Evidence column only is not a change |
| 3. Words the business uses | A word that a merged requirements document, a decision record or a standard defines. The cell restates that definition and adds nothing | A source adds, changes or removes a definition. A word that a source uses and does not define stays out. The pull request lists it |
| 4. Outside the estate | One row for each `external:<host>` Provider in survey section 2 | A survey adds or removes such a call |

Rules against noise:

- Do not reword a sentence that is correct.
- Do not fix style, order or formatting.
- Do not remove a person's text unless a source contradicts it.
- Keep a column that a person added, such as `Also called`. Fill a cell in it only from a source
  that states the value.

## Output

- Exit 0 from the script: one line, "the overview is current at `<T>`". No branch.
- Every answer "no": one line for each listed file, with the reason it needs no change. No branch
  and no pull request.
- Otherwise: one page written or edited at `docs/estate/overview.md`, one pull request in the hub
  on `context/estate-overview`, and one line that reports `P`, `T`, the number of edits and what
  `check-context` said.

## Stopping condition

Done when the script exits 0, when every answer is "no", or when the pull request is open and
`check-context.mjs --offline` exited 0 on the branch. Not done, and nothing opened, when a
precondition fails or the script exits 2, 3 or 4.

## Never

- Never merge the pull request. A merge is a person's act.
- Never read spoke code or a spoke README. The surveys describe each spoke.
- Never edit the page when the script exits 0.
- Never open a pull request when every answer is "no".
- Never reword a correct sentence.
- Never change a check, or the template, to make the page pass.
- Never write a person's name. "Who to ask" and "who owns it" are roles.
